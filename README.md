# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

##### Модели данных

##### Класс ProductCatalog (хранение товаров, которые можно купить в приложении)

Поля класса:
`items` — приватное поле, хранящее массив всех товаров. Инициализируется пустым массивом. 
`selectedProduct` — приватное поле для хранения товара, выбранного для подробного отображения. Изначально null. 

Методы:
`setItems(products)` — принимает массив товаров и сохраняет его в поле `items`. Тип параметра — `IProduct[]`, возвращаемое значение — `void`.  
`getItems()` — возвращает текущий массив товаров из поля items. Возвращаемый тип — `IProduct[]`. 
`getItemById(id)` — ищет товар по ID в массиве `items` с помощью метода `find()`. Если товар найден — возвращает его, иначе — `null`. Тип параметра — `string`, возвращаемый тип — `IProduct | null.`
`setSelectedProduct(product)` — сохраняет переданный товар в поле `selectedProduct`. Тип параметра — `IProduct`, возвращаемое значение — `void`. 
`getSelectedProduct()` — возвращает товар из поля `selectedProduct`. Если товар не выбран, возвращает `null`. Возвращаемый тип — `IProduct | null`. 

##### Класс Cart (хранение товаров, которые пользователь выбрал для покупки)
Конструктор:
`constructor() { this.items = []; }` -  инициализирует корзину с пустым массивом товаров.

Поле класса
`items: IProduct[]` — приватное поле, хранящее массив товаров в корзине. Инициализируется пустым массивом

Методы: 
`getItems(): IProduct[] `
Назначение: возвращает массив всех товаров, находящихся в корзине. 
Возвращаемое значение: копия массива товаров `(IProduct[])`.
Особенность: возвращается копия массива `([...this.items])`, чтобы предотвратить прямое изменение внутреннего состояния корзины извне.

`addItem(product: IProduct): void`
Назначение: добавляет переданный товар в массив корзины. 
Параметр: `product` — объект товара типа `IProduct`.
Принцип работы: товар добавляется в конец массива `items`.

`removeItem(product: IProduct): void`
Назначение: удаляет переданный товар из массива корзины. 
Параметр: `product` — объект товара, который нужно удалить.
Принцип работы: находит индекс товара по id и удаляет его из массива с помощью `splice()`. Если товар не найден, ничего не происходит.

`clear(): void`
Назначение: очищает корзину, удаляя все товары.
Принцип работы: массив `items` перезаписывается пустым массивом.

`getTotalPrice(): number`
Назначение: рассчитывает общую стоимость всех товаров в корзине. 
Возвращаемое значение: число — сумма цен всех товаров. 
Принцип работы: использует `reduce()` для суммирования значений `price` всех товаров. Если цена `null`, учитывается как 0.

`getItemCount(): number`
Назначение: возвращает количество товаров в корзине (общее число позиций). 
Возвращаемое значение: число — количество товаров.

`hasItem(id: string): boolean`
Назначение: проверяет, есть ли товар с указанным id в корзине. 
Параметр: id — идентификатор товара.
Возвращаемое значение: true, если товар найден, false — если нет.
Принцип работы: использует метод some() для проверки наличия товара с совпадающим id\

##### Класс Buyer (данные покупателя, которые тот должен указать при оформлении заказа)
Конструктор:
`constructor() { this.data = { payment: null, address: '', phone: '', email: '' }; }` - инициализирует покупателя с пустыми/нулевыми значениями всех полей.

Поля класса
`data: IBuyer` — приватное поле, хранящее данные покупателя. Инициализируется значениями по умолчанию:
`payment: null` — вид оплаты (может быть 'card' или 'cash', изначально null); 
`address: ''` — адрес доставки (изначально пустая строка); 
`phone: ''` — телефон (изначально пустая строка); 
`email: ''` — email (изначально пустая строка). 

Методы 
`setData(partialData: Partial<IBuyer>)`
Назначение: сохраняет данные покупателя. Позволяет обновить одно или несколько полей, не затрагивая остальные.
Параметр: `partialData` — объект с частичными данными покупателя `(Partial<IBuyer>)`.
Принцип работы: использует оператор spread для слияния существующих данных с новыми.
Альтернативные методы для установки отдельных полей:

`setPayment(payment: TPayment)` — сохраняет вид оплаты; 
`setAddress(address: string)` — сохраняет адрес; 
`setPhone(phone: string)` — сохраняет телефон; 
`setEmail(email: string)` — сохраняет email. 

`getData(): IBuyer`
Назначение: возвращает все данные покупателя. 
Возвращаемое значение: копия объекта с данными покупателя (IBuyer).

`clearData()`
Назначение: очищает все данные покупателя, сбрасывая их к значениям по умолчанию.

`validate(): ValidationErrors`
Назначение: проверяет валидность всех полей и возвращает объект с ошибками.
Правила валидации: поле валидно, если оно не пустое (для строк — не пустая строка, для payment — не null). 
Возвращаемое значение: объект `ValidationErrors` с ключами — именами полей и значениями — сообщениями об ошибках. Если поле валидно, оно отсутствует в объекте. 

`isValid(): boolean`
Назначение: быстрая проверка валидности всех данных.
Возвращаемое значение: true, если все поля валидны (нет ошибок), false — в противном случае.

Вспомогательные функции
`getBasketCards(): HTMLElement[]` — создаёт карточки товаров для корзины из данных модели корзины.
`getBasketData(): IBasket` — подготавливает данные для отрисовки корзины: карточки товаров, общую стоимость и признак блокировки кнопки оформления.
`getOrderFormData(): TOrderForm` — подготавливает данные для формы способа оплаты и адреса: значения полей, признак валидности и текст ошибок.
`getContactsFormData(): TContactsForm` — подготавливает данные для формы почты и телефона: значения полей, признак валидности и текст ошибок.

Обработка событий моделей данных
`catalog:changed` — создаёт карточки для всех товаров каталога и выводит их на главной странице.
`preview:changed` — создаёт карточку подробного просмотра выбранного товара и открывает её в модальном окне. Текст кнопки зависит от состояния товара: «Купить», «Удалить из корзины», если товар уже в корзине, или «Недоступно», если у товара нет цены (в этом случае кнопка заблокирована).
`cart:changed `— обновляет счётчик товаров в шапке и содержимое корзины.
`cart:changed` — обновляет значения полей, ошибки валидации и состояние кнопок в обеих формах оформления заказа.

Обработка событий представлений
`card:select` — сохраняет выбранный товар в модели каталога как товар для подробного просмотра.
`preview:button-click` — получает из модели каталога товар для просмотра, по данным модели корзины решает, добавить товар в корзину или удалить его, и закрывает модальное окно.
`cart-item:delete-click` — удаляет товар из корзины.
`cart:open` — открывает корзину в модальном окне. Список товаров при этом не перерисовывается: он обновляется только в обработчике basket:changed.
`cart:order` — открывает в модальном окне форму способа оплаты и адреса без передачи новых данных: форма обновляется в обработчике buyer:changed.
`form:change` — сохраняет изменённые поля в модели покупателя.
`order:submit` — открывает в модальном окне форму почты и телефона без передачи новых данных.
`contacts:submit` — собирает данные заказа из моделей покупателя и корзины и отправляет их на сервер. После успешного ответа очищает корзину и данные покупателя и показывает сообщение об успешном оформлении заказа.
`checkMark:close` — закрывает модальное окно.
`modal:close` — закрывает модальное окно.
